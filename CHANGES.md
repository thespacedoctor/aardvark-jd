
## Release Notes

**Unreleased**

- **FEATURE:** tab completion for `bash` and `zsh`, installed with `eval "$(aardvark completion zsh)"` (or `completion bash`) in your shell's rc file. Subcommands complete by name, and `<domainLetter>`, `<area>`, `<category>` and `<ref>` complete from the live SQLite index - so `aardvark archive A11.<TAB>` offers exactly the IDs that exist. The shells call a hidden `__complete` subcommand, intercepted before docopt (which would reject an undeclared command) and before `fundamentals.tools`, so a keystroke never pays for settings-file creation, logging setup or a schema migration; the index is opened read-only, an explicit `-s` on the line being typed is honoured, and every failure is swallowed silently rather than spilling a traceback into the completion buffer.
- **FEATURE:** new `archive <ref>` command, retiring an area, category or ID and **freeing its Johnny Decimal number for reuse**. The folder moves into the nearest reserved `09_archive🗄️` - a category's own for an ID, the parent area's system folder for a category, the domain's for an area - which is the first thing ever to write into that scaffolding. The row leaves `areas`/`categories`/`ids` for a new `archived_entities` table rather than being flagged in place: the live tables carry `UNIQUE (domain, ac_number[, item_number])`, so a row cannot both stay put and surrender its number, and - more importantly - all three sync engines adopt-or-create *by name*, so one query that forgot an `archived` filter would silently rebuild the archived structure on the next sync. Removing the row makes that whole class of bug impossible and evicts it from the search index for free. Archived folders are datestamped (`A11.10_cardiologist__archived_20260820`), which is load-bearing rather than decorative: once a number is reused, the next entity to be archived would otherwise collide with the first. Destructive and one-way - there is no `unarchive` - so it confirms interactively unless given `-y`.
- **FEATURE:** new `connect_gdrive <clientId> <clientSecret>` and `gdrive_sync` commands, mirroring the folder tree into Google Drive - **folders only, never documents**. The whole system lands in one Drive folder named after it; `00_INDEX` is never mirrored (it holds `aardvark.db`); and of each system folder's ten reserved `00`-`09` subfolders only `01_inbox📥`, `04_templates📐` and `09_archive🗄️` are created. Every Drive folder is matched on `(parent, name)` against a live listing before anything is created, so a re-run repairs rather than duplicates and a folder made by hand is adopted. Authorisation uses a loopback listener on an ephemeral `127.0.0.1` port rather than Dropbox's paste-the-code flow, which Google does not offer; the client is hand-rolled on `requests` like every other client here, so no new dependency. The Drive URL now rides alongside Finder/Dropbox/Craft/Todoist in synced Craft link rows and Todoist descriptions, and `open` opens it too - which makes the mandated sync order `gdrive` -> `todoist` -> `craft`, since each of the last two embeds a link written by the one before.
- **FEATURE:** `search` with no argument now prints the whole index as a tree, and `search <ref>` accepts a Johnny Decimal reference at every level - a bare domain letter (`A`), an area (`A10-19`) or a category (`A11`) prints that subtree, and an ID (`A11.10`) prints its path as before. A ref-shaped term that matches nothing falls through to the existing keyword search, so `search A` can still find the word "A". Reserved `.00`-`.09` system IDs never appear, since they live in `system_folders` rather than `ids`.
- **FEATURE:** `aardvark open` with no path now opens an arrow-key picker, drilling down domain -> area -> category -> ID, with "open this level" offered at each step so Enter can stop anywhere. Hand-rolled on `termios`/`tty` (no new dependency), drawn to stderr so stdout stays pipeable, and the terminal is always restored. Whichever entry contains the current directory starts highlighted, so the old behaviour - open what I am standing in - is still two keystrokes away; passing a path explicitly, or running without a terminal, behaves exactly as before.
- **ENHANCEMENT:** `--help` now shows only the everyday commands, with setup and maintenance verbs behind the new `--help-all`. docopt derives its grammar from the `Usage:` block, so every command remains parseable - the abridged screen is display-only, and prunes `Arguments:` entries no surviving usage line mentions. A new `commands.py` is the single source of truth for the grouping and for completion, and a test asserts it matches the docopt string exactly so the two cannot drift.
- **ENHANCEMENT:** `craft_sync` now adopts an existing Craft document when its link row is missing - the state left by a rebuilt index, the v4 migration, or `archive` clearing link rows - instead of blindly creating a duplicate beside it. Folders and Todoist projects already worked this way; documents were the remaining gap. `GET /documents` is unverified against a live space and may not exist at all, so `CraftClient.list_documents` returns an empty list on failure and the caller degrades to exactly the previous create-anyway behaviour. A document filed nowhere (the space-root index) still cannot be looked up, so it is the one document a rebuild recreates.
- **REFACTOR:** `new_project` is now `add_project`, matching `add_area`/`add_category`/`add_id`. The old name is gone entirely, as with the `<domain>` argument before it.
- **REFACTOR:** the three Johnny Decimal allocators (`next_area_decade`, `next_category_number`, `next_id_number`) now hand out the **lowest free** number rather than `max(existing) + 1`. This is a no-op for every system created so far - nothing could ever be removed from the index, so no gaps could exist and the two rules agreed - but without it `archive` could not actually free a number, since a high-water mark steps straight over the gap it leaves. `set_emoji.rename_folder_and_reindex` is likewise now a thin wrapper over a new, general `folders.move_folder_and_reindex`, which can move a folder to a different parent (with a cross-filesystem fallback) rather than only renaming it in place; the careful commit-before-rename ordering and compensating write are unchanged.
- **REFACTOR:** `db._migrate_schema` walks an ordered `_MIGRATIONS` ladder instead of comparing the stored version against string literals, so adding a migration no longer means editing the conditions guarding the previous ones. Schema is now v5, adding `archived_entities` and `gdrive_links`; both are plain additive `CREATE TABLE IF NOT EXISTS`, so an existing database picks them up with no rebuild.
- **FIXED:** `codes.is_jd_ref` answers "is this an area or category?" - it has always returned `False` for an ID code like `A11.10`, which is correct for telling a Johnny Decimal ref from a system folder key, but meant a new `archive A11.10` or `search A11.10` silently failed to resolve. Added `codes.is_id_ref` and `codes.split_id_ref` alongside it rather than widening `is_jd_ref`, whose existing meaning `set_emoji` depends on.
- **DOCS:** `docs/source/usage.md` had drifted from the real command-line interface (it still documented `new_project`'s pre-`-t` signature and omitted the Todoist commands). It is regenerated, and a test now asserts it matches `cl_utils.__doc__` so it cannot silently rot again.

- **FEATURE:** aardvark can now mirror into Todoist alongside craft.do, for the actionable side reference material doesn't cover. Connect with the new `connect_todoist <apiToken>` command, using a personal API token from Todoist's Settings -> Integrations -> Developer tab; re-run on demand with the new `todoist_sync` command. Since a personal Todoist plan has no Workspaces, the mirror lives under one top-level project named after the aardvark system, with `03 AREAS` (areas and their categories, nested two deep) and `02 PROJECTS` (every project ID, flat, skipping the project areas/categories above it) nested inside it - `01 INBOX`, `04 RESOURCES`, `09 ARCHIVE` and every `00-09` system folder are never mirrored. Each mirrored Todoist project's description carries a Finder/Dropbox/Craft link row back to its sibling objects, and the reverse Todoist link is added to the existing Finder/Dropbox row on synced Craft documents - `todoist_sync` always runs before `craft_sync` on every mutating command so the Craft link row can embed it. `aardvark open` now opens both the linked Craft entity and the linked Todoist project, whichever are synced.
- **ENHANCEMENT:** an ID now mirrors into Craft as a folder, with a single `00 Index` document inside it carrying its Finder/Dropbox/Todoist link row - matching every other level of the hierarchy - rather than as a bare top-level document with nothing to hold anything created inside it. An earlier version's Craft link for an ID is cleared on the next `craft_sync` (bumping the SQLite schema to v4) and rebuilt in the new shape; the orphaned old top-level document itself has to be deleted by hand in the Craft app, since the API can't delete or convert it.
- **REFACTOR:** `new_project` now reads its zip templates from the project category's own reserved `04_templates` system ID (e.g. `P11.04_templates/`) rather than a single pool shared across the whole `projects` domain, so each category curates its own template set. `<projectTitle>` is now a mandatory positional argument and the template is chosen with the new `-t, --template <templateName>` flag instead of a second trailing positional - `new_project P11 blank "My Project"` becomes `new_project P11 "My Project" -t blank` (or just `new_project P11 "My Project"` for the interactive picker, whose blank option is now labelled "New blank project").
- **REFACTOR:** the `<domain>` positional argument is gone from every command - the domain now comes from the ref's mandatory domain letter prefix (`A` areas, `R` resources, `P` projects), so `add_id areas 11 ...` becomes `add_id A11 ...`, `add_category areas 10 ...` becomes `add_category A10-19 ...` and `set_emoji areas 10 🏥` becomes `set_emoji A10-19 🏥`. `add_area` takes the bare letter (`add_area A "Health" "..."`), and `set_emoji` tells a system folder key from a Johnny Decimal ref by whether it carries a letter, so its old `system` domain word is gone too. A ref with no letter prefix is now an error rather than being silently read as the domain given alongside it, a ref whose letter contradicts the command it is used in is rejected, and `new_project` requires its `P` prefix. The legacy dotted form (`A.11`) still parses everywhere.
- **FIXED:** the Finder link in synced Craft documents ("The URL is invalid. Hookmark could not handle it.") - `hookmark_url()` was building three parts of the `hook://file/...` URL wrong, found by decoding all 112 `hook://file/` bookmarks in the live Hookmark database: the id must be exactly 9 characters (an 8-character id fails a parse-level length check before Hookmark even tries to resolve anything), `p=` is base64 of only the parent's last two path components, not the full parent path, and `n=` is the plain name percent-encoded (alphanumerics only left unescaped), not base64.
- **FEATURE:** new `open [<path>]` command resolves a filesystem path (default: the current directory) back to its linked Craft folder/document and opens it - the reverse of `craft_sync`'s mirror, via a new `locate.entity_for_path` lookup over every entity's stored `folder_path`. Also installed as a second `av` entry point, an alias for `aardvark` covering every subcommand.
- **FEATURE:** every document `craft_sync` writes to now carries a Finder link back to its own on-disk folder, as a single markdown line just below the title (a `hook://file/...` Hookmark link, since Craft doesn't open `file://` links when clicked - Hookmark falls back to locating the file via Spotlight from the base64-encoded path/name baked into the link, so only meaningful on a Mac with Hookmark installed). When the aardvark system root sits inside a Dropbox-synced folder, a Dropbox share link is added alongside it - set up with the new `connect_dropbox <appKey> <appSecret>` command, which runs a one-time PKCE browser flow and stores a long-lived refresh token (Dropbox access tokens expire after 4 hours). Dropbox share links are cached in a new `dropbox_links` table so they're minted once, not on every sync; the link row itself is tracked per-entity via new `craft_links.links_markdown`/`craft_block_id` columns and only rewritten when it changes.
- **FEATURE:** Projects is now a fully fledged Johnny Decimal domain, identical in structure to Areas/Resources - domain letter `P`, decade-based project areas (`P10_19_...`), categories (`P11_...`) and numbered project IDs (`P11.10_...`), created with `new_project <category> [<templateName>] [<projectTitle>]` in place of the old one-step `new_project [<templateName>] [<projectTitle>] [-e <emoji>]` flow that dropped projects flat under `02_PROJECTS🚀`. Project ID folders carry no emoji, matching every other Johnny Decimal ID. `repair_emoji` migrates an existing system's `02_PROJECTS🚀/00_09_system⚙️` onto the new `P00_09_system⚙️`-prefixed naming, and `craft_sync` now mirrors the Projects domain the same nested way as Areas/Resources.
- **REFACTOR:** removed the flat `projects` table and its `insert_project`/`get_project_by_title`/`list_projects`/`update_project_emoji` helpers, search triggers and dedicated `craft_sync`/`set_emoji` code paths - projects are now plain rows in the shared `areas`/`categories`/`ids` tables, with no special-case metadata (`template_used`/`status` tracking and the `-e <emoji>` flag on `new_project` are gone). `initialise_schema` migrates an already-initialised database onto the widened schema automatically on next run (rebuilding `areas`/`categories`/`ids` against the new `CHECK` constraint and dropping the legacy `projects` table), so no manual database surgery is required.
- **FEATURE:** areas and categories under `areas`/`resources` are now named `<X><AC>_<title><emoji>` - domain letter, lowercase, underscores instead of spaces (e.g. `A10_19_health🏥`, `A11_doctors🩺`); ID folders drop the emoji too (`A11.10_cardiologist`). Every area now gets its own reserved `<X><D0>_system⚙️` folder, and every category gets ten reserved system IDs `.00`-`.09` reusing the same names/emoji as the domain-level `00_09_system` subfolders - so user-created IDs now start at `.10`, not `.01`. `repair_emoji` renames any area/category/ID whose on-disk name has drifted from its stored title/emoji/numbers and backfills any missing reserved scaffolding, so it's now also the migration path for systems created before this change - run it once against an existing system (on a copy first, if in doubt).
- **ENHANCEMENT:** Craft folders and documents now mirror their on-disk folder names, with underscores rendered as spaces and an area's decade range kept readable as a hyphen (`01_INBOX📥` → `01 INBOX📥`, `A10_19_health🏥` → `A10-19 health🏥`). The emoji rides in the name itself because Craft's API has no folder icon field - the `icon` argument previously sent was silently ignored, and has been dropped.
- **FIXED:** Craft folders were unreachable via their stored links and never nested correctly, because `POST /folders` returns an id that stops resolving once the Craft app syncs the new folder and re-keys it. Folder identity now comes from a `GET /folders` lookup on name and parent at the start of every sync, so each run adopts what is already in the space, refreshes any id that changed underneath it, and repairs a broken tree rather than duplicating it. Document ids are unaffected and still come straight from the create response.
- **FIXED:** every "00 Index" entry linked to `None`, because neither create endpoint returns a URL. Folders are now linked with a `craftdocs://openfolder` deep link, and documents with the block deep link built from `GET /connection`'s URL templates.
- **FEATURE:** new `connect_craft <apiUrl> <apiToken>` and `craft_sync` commands, mirroring the aardvark folder tree into a craft.do space. Craft spaces can't be created via API, so the five root PARA folders become top-level Craft folders instead; areas and categories nest as folders below them, and IDs become Craft documents named with their `X.AC.ID` code. A `00 Index` document at each level lists the level directly below it, one level deep, with each child's code and title linking to its Craft folder or document, written via Craft's `/blocks` endpoint. `connect_craft` takes both a connection's unique API URL and its token - Craft has no shared global API endpoint, so the URL has to be copied from the Connections tab rather than guessed. Once connected, `add_area`, `add_category`, `add_id`, `set_emoji` and `new_project` all push to Craft automatically; a failed push warns rather than aborting the local command, since the filesystem and SQLite index remain the source of truth.
- **REFACTOR:** dropped the period after the domain letter across every code and on-disk name - `A.10-19` → `A10-19`, `A.11` → `A11`, `A.11.10` → `A11.10` (the second period, before the item number, stays), and the three root skeleton folders lose theirs too (`02_P.ROJECTS` → `02_PROJECTS`, `03_A.REAS` → `03_AREAS`, `04_R.ESOURCES` → `04_RESOURCES`). Every parser still accepts the old dotted form as well as the new one, so both styles keep working during migration; run `repair_emoji` to rename an existing system onto the new form.
- **FIXED:** `connect_craft` only wrote `craft.enabled`/`api_url`/`api_token` back to the settings file when `-s` was passed explicitly - unlike `init`, which already falls back to the default `~/.config/aardvark/aardvark.yaml`. A bare `connect_craft <url> <token>` looked like it worked (the initial sync ran) but nothing was saved, so `craft.enabled` was never on for later commands and every auto-push silently no-op'd. `connect_craft` now falls back to the same default settings file `init` uses.
- **FIXED:** `repair_emoji` never pushed to Craft at all, even when connected - the one command most likely to need a fresh sync, since it's also the migration path for the dotted-to-dotless renaming above, now auto-pushes like every other mutating command.
- **FIXED:** the six `search_index` triggers that build a row's `code` string in raw SQL (`areas_ai`/`au`, `categories_ai`/`au`, `ids_ai`/`au`) were declared `CREATE TRIGGER IF NOT EXISTS`, so an existing database silently kept its old trigger bodies forever - including the just-dropped domain-letter period - with no way to pick up a schema change. `initialise_schema` now drops and recreates every search trigger on each call.
- **FIXED:** every "00 Index" document stayed permanently empty (or stuck on its very first entry), because Craft's `POST /blocks` splits multi-line markdown into one sibling block per line rather than one block for the whole thing - confirmed empirically against a real space - and `_refresh_index` only ever tracked and updated the first of those. There is also no atomic "replace page content" call. `_refresh_index` now reads a document's current top-level content via the new `CraftClient.get_block`, deletes all of it via the new `CraftClient.delete_blocks`, and inserts the fresh markdown - read, delete, insert in place of an update. `craft_block_id` is no longer written or read anywhere (the `craft_links` column stays, just unused), and `PUT /blocks`/`update_block` are gone.
- **FEATURE:** the domain-level and area-level `<X>_system` folders, and their ten reserved subfolders (`.00_index`-`.09_archive`), now mirror into Craft three levels deep, each subfolder as a Craft folder or document per its declared kind in `paths.SYSTEM_SUBFOLDERS`. The reserved `.00_index` document at each of these levels becomes that level's index (domain root lists its areas, an area lists its categories) - the old free-standing "00 Index" document at area level is gone. A category has no system folder of its own, so its ten reserved subfolders (including its `.00_index`, now the category's own index) sit directly inside the category folder, alongside its user-created IDs. The space-root index and the flat projects listing are unchanged.

**v0.3.0 - August 17, 2026**

- **ENHANCEMENT:** renumbered the six root skeleton folders onto the same two-digit, uppercase scheme already used inside each `00_09_system` folder: `00_index`→`00_INDEX`, `01_inbox`→`01_INBOX`, `P.ROJECTS`→`02_P.ROJECTS`, `A.REAS`→`03_A.REAS`, `R.ESOURCES`→`04_R.ESOURCES`, `09_archive`→`09_ARCHIVE` (numbers 05-08 stay reserved). Run `repair_emoji` to renumber an existing system.
- **FIXED:** `06_bin` was described as "items pending deletion" with a 🗑️ trash-can emoji; it's actually a Unix-`/bin`-style folder for scripts and executables. Description and emoji (now 📜) corrected; the folder's base name is unchanged.
- **FIXED:** `find_db_path` now locates the index folder by a case-insensitive scan rather than an exact-case glob, so it can still find a system's database before that system has been renumbered onto the new uppercase scheme.
- **FIXED:** a rename that only changes a folder's case (e.g. `01_inbox` → `01_INBOX`) no longer raises a false "already exists" error. On a case-insensitive filesystem - the macOS default - the old and new paths resolve to the same directory entry; the collision check now uses `os.path.samefile` to tell that apart from an actual collision with something else.

**v0.2.1 - August 17, 2026**

- **FIXED:** `repair_emoji` failed with `sqlite3.OperationalError: attempt to write a readonly database` against an existing system, because renaming `root.index` - the folder `aardvark.db` itself lives in - permanently write-poisons the open connection for every write that follows, even though the rename that caused it succeeds. `root.index` is now always repaired last, and `set_emoji`'s index write is committed before the physical rename rather than after.
- **FIXED:** dropped the space between a folder's title and its emoji (`Health🏥`, not `Health 🏥`).

**v0.2.0 - August 17, 2026**

- **FEATURE:** new `set_emoji` command, changing the emoji on an existing area, category, project or static system folder. Renaming a folder invalidates the stored path of everything nested inside it, so the rename and a path rewrite across every descendant row land in a single transaction, with the directory move undone if any of the index work fails.
- **FEATURE:** new `repair_emoji` command, resetting every static system folder in an existing system to its declared emoji. Run this once against any system created before v0.2.0.
- **FEATURE:** folder emoji for user-supplied titles are now suggested by Claude, falling back to the offline keyword search whenever the API cannot be reached - the `anthropic` package missing, no credentials, no network, a policy refusal, or a reply that is not exactly one emoji. Set `emoji: use_llm: false` in the settings file to stay offline.
- **FEATURE:** new `--emoji` flag on `add_area`, `add_category` and `new_project`, using a given emoji verbatim and skipping both the suggestion and the prompt. Without it, an interactive session shows the suggestion to accept or replace, while a non-interactive one accepts it silently.
- **FIXED:** the 39 static system folders created by `init` were routed through the keyword picker, which had no match for 11 of their 14 distinct titles and so left most of them on the generic folder emoji, and picked a backhand-pointing-down hand for "Index". Their emoji are now declared alongside the skeleton itself.
- **ENHANCEMENT:** the offline picker now singularises before giving up, so plural titles that used to fall back ("Films", "Links", "Flights") resolve. Exact matches still win, leaving "Books" as a stack of books rather than one book.
