# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

`aardvark-jd` is a CLI (`aardvark`, alias `av`) that manages a PARA + Johnny Decimal
folder tree on disk, indexed in a per-system SQLite database, and optionally mirrored
to craft.do, Google Drive and Todoist. Distribution name `aardvark-jd`, import package
`aardvark_jd`, command `aardvark`.

The repo is checked out at `~/git_repos/_packages_/python/aardvark-jd` and is also
reachable through the symlink `git_repos/aardvark-jd/` inside the surrounding PARA
project folder. Run all commands below from the repo root.

## Commands

- Install for development (needs Python >= 3.14): `pip install -e ".[dev]"`
- Run the whole test suite: `pytest` (discovers `aardvark_jd/tests/`)
- Run one test: `pytest aardvark_jd/tests/test_add_area.py::test_add_area_invalid_domain`
- Skip the slow tiers: `pytest -m "not full"` or `pytest -m "not slow"`
- Coverage: `pytest --cov=aardvark_jd` (`pytest-cov` is in the `tests` extra)
- `makefile` targets `litetest` / `fulltest` add SVG profiling and need `gprof2dot` + Graphviz `dot`; not for routine runs
- Build the docs: `cd docs && make html`
- CLI help: `aardvark --help` is abridged; `aardvark --help-all` lists every command

`aardvark_jd/__version__.py` is generated by `setuptools-scm` from git tags. Do not
hand-edit it. `nose2.cfg` exists but pytest is the primary runner.

## Architecture

### Command dispatch

- The docopt grammar in `cl_utils.__doc__` (`Usage:` block) is the single source of the
  CLI parse. `commands.py` is a parallel table holding what docopt has no opinion about:
  help grouping (`common` vs `advanced`) and per-argument tab-completion behaviour.
  `tests/test_commands.py` asserts the two stay in sync — every `Usage:` command must
  appear in `commands.names()` exactly.
- `cl_utils.main` handles completion and `--help` / `--help-all` *before* `fundamentals.tools`
  runs: a tab completion must be fast and strictly read-only (no settings-file creation,
  logging setup or schema migration).
- Otherwise `fundamentals.tools(...).setup()` returns `(arguments, settings, log, dbConn)`.
  User settings YAML lives at `~/.config/aardvark/aardvark.yaml`, seeded from
  `aardvark_jd/default_settings.yaml`. The active system's root is
  `settings["system"]["root_path"]`.
- Every non-`init` command re-asserts the Dropbox ignore on the index dir
  (`dropbox_ignore.assert_index_ignored`), then opens `<root>/00_INDEX🗂️/aardvark.db`
  via `db.get_connection` + `db.initialise_schema`, then routes through `_dispatch`
  (or the sync/connect branches in `main` itself).

### Worker modules

One lowercase class per command (`add_area`, `add_id`, `archive`, `craft_sync`,
`initialiser`, ...), constructed with keyword args, all real work in a `.get()` method
that returns a tuple. This is the `fundamentals` idiom used throughout. `cl_utils._dispatch`
instantiates the worker, calls `.get()`, prints the result, and for mutating commands
calls `_hand_off_sync`.

### Data model (`db.py`)

- `areas` / `categories` / `ids` — one row per Johnny Decimal entity, keyed by
  `UNIQUE (domain, ac_number[, item_number])`. Domains: `areas` (letter `A`),
  `resources` (`R`), `projects` (`P`).
- Archiving **moves** a row out of the live table into `archived_entities`. That is what
  frees the Johnny Decimal number for reuse, and it means every existing walk and all
  three sync engines skip archived entities without needing an `archived` filter (a
  missed filter would silently recreate archived structure on the next sync).
- `search_index` is FTS5 (`porter unicode61`) with a plain indexed-table fallback if the
  SQLite build lacks FTS5; kept current by AFTER INSERT/UPDATE/DELETE triggers that are
  dropped and recreated on every `initialise_schema` call.
- Schema is versioned: bump `_SCHEMA_VERSION` and append to the `_MIGRATIONS` ladder when
  an already-initialised DB can't pick up a change from the `IF NOT EXISTS` DDL alone.
- `busy_timeout` is 5000 ms on both the read/write and the `mode=ro` completion paths.
  WAL is deliberately **not** enabled — the tree is Dropbox-synced and `-wal`/`-shm`
  sidecars corrupt across machines.
- `craft_links` / `gdrive_links` / `todoist_links` / `dropbox_links` map entities to their
  mirrored counterparts; `sync_drift` records each mirror's last success/failure.

### Johnny Decimal numbering and folders

- `codes.py` — parse/format references (`A`, `A10-19`, `A11`, `A11.10`); the domain letter
  is mandatory on every ref.
- `folders.py` — next-number allocation, `slugify`, folder creation, exhaustion errors.
- `paths.py` — the fixed root skeleton (`SYSTEM_SKELETON`) and path resolution against the
  `system_folders` table.
- Every non-ID folder name ends with an emoji. `emoji_picker.resolve_emoji` tries an
  offline keyword index built from `emoji.EMOJI_DATA` first, then optionally asks Claude
  (`claude-opus-5`, `low` effort, 15 s timeout, 0 retries, falls back to `📁`). Uses the
  `anthropic` SDK — needs `ANTHROPIC_API_KEY`.
- `spell_check.checked_title` runs *before* the emoji step (accepting a correction changes
  the title the emoji and folder name derive from). Ships a British English wordlist in
  `aardvark_jd/resources/wordlists/`, checks only tokens >= 6 chars at edit distance 1,
  and records dismissals permanently in `<root>/.aardvark-vocabulary`. Toggle with
  `spell_check.enabled`.

### Remote mirroring and background sync (see `docs/adr/0001-*`)

- The seven mutating commands (`add_area`, `add_category`, `add_id`, `add_project`,
  `set_emoji`, `repair_emoji`, `archive`) do their local filesystem + SQLite work, then
  spawn a detached `av craft_sync` (which already runs `gdrive -> todoist -> craft` in the
  mandated order) and exit. `-w` / `--wait` forces the foreground path and exits non-zero
  if a mirror failed (the entity is still created — it just didn't sync).
- At most one sync runs at a time, held by a lockfile beside `aardvark.db` in `00_INDEX🗂️`
  (Dropbox-ignored, so per-machine). A mutation arriving mid-sync sets a pending flag
  rather than starting a second writer; the running sync re-checks it and goes round again.
- Failures are recorded per-mirror in `sync_drift` with a reason class
  (`rate-limited` / `auth` / `network` / `unknown`), rendered by `browse`/`fd`, and
  surfaced as a one-line warning on the next command.
- Client modules (`craft_client.py`, `gdrive_client.py`, `todoist_client.py`,
  `dropbox_client.py`) are hand-rolled on `requests` and all route through
  `http_retry.request_with_retry` for timeouts, retry (429/5xx, and Drive's rate-limit
  `403`), and a shared per-run backoff budget. `oauth.py` holds the PKCE + loopback pieces.
- `connect_*` and the explicit `*_sync` commands stay in the foreground and take the same
  lock.

### Other

- `open` / `locate.py` / `open_craft.py` — map a filesystem path back to its mirrored
  Craft/Drive/Todoist entities via longest-prefix match over
  `db.entity_rows_for_path_prefix`.
- `browse.py` — the arrow-key interactive picker built on `picker.py`, seeded from the
  current directory when it resolves to an indexed folder.
- `completion.py` — emits the bash/zsh completion script; the hidden `__complete`
  subcommand resolves completions read-only.

## Conventions

- Python >= 3.14. Naming: `camelCase` locals, `snake_case` functions, lowercase worker
  classes, `UPPERCASE` inline comments (the codebase already follows the global rules).
- Docstrings follow the `fundamentals` style: `*one-line summary*`, then
  `**Key Arguments:**` / `**Return:**` / `**Usage:**` sections.
- `CHANGES.md` uses `**TYPE:**` entries (`FEATURE`, `ENHANCEMENT`, `REFACTOR`, `FIXED`,
  `DOCS`, `TEST`), no mid-sentence line breaks. An `**Unreleased**` block sits at the top.
- Architecture decisions go in `docs/adr/`.
- Adding a CLI command: add the `Usage:` line and `Commands:` blurb to `cl_utils.__doc__`,
  add the matching entry to `commands.py` (parity is test-enforced), wire it into
  `_dispatch`, and add a worker module.

## Tests

- pytest, tests in `aardvark_jd/tests/`, one `test_<module>.py` per module.
- Integration-style: fixtures build a real system with `initialiser(...).get()` in
  `tmp_path` and use a real SQLite index rather than mocking the DB.
- `utKit.py` overrides `fundamentals.utKit` for module-local `input/` and `output/` dirs.
- Markers: `slow`, `full`, `serial`.
